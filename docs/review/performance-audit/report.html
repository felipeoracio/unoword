      rootCause

      severity

      Critical

      finding

      Business revision conflicts are raised with SQLSTATE 40001 in workspace RPC functions. That code requests transaction retry; the Hasql transaction driver retries it. A stale document revision cannot resolve by retrying the same mutation.

      evidence

      • 83+ million rollback transactions since the recorded statistics epoch.

      • 575.04 rollbacks/second across an 80.14-second sample. These are internal transactions, not distinct browser API requests.

      • Three active PostgREST workers sampled executing workspace_save_document.

      • Recent sampled PostgreSQL error logs: 900 revision_conflict records in a 15-minute window. Log sampling/rate limits mean this is not an exhaustive transaction count.

      • writing_documents index scans track the failed attempts despite only 24 document rows.

      • Recent completed API logs showed mainly scheduled ingestion/Substack activity; failed database transactions are not recorded as successful statement executions.

      fix

      Return custom SQLSTATE PT409 for expected business conflicts in six existing functions (seven raise sites). Preserve successful saves, mutation replay, ownership, row locks, RLS, and revision checks. Genuine PostgreSQL serialization failures remain retryable. This narrow correction is now applied in production.
